# 今日总结：Vercel 大文件上传 413 与 Blob 直传修复

今天处理了 `prompt-lens` 里一个很典型的大文件上传问题。

用户在上传一个 4.5MB 以上的视频文件时，线上报错：

```text
Error: Upload failed (413): Request Entity Too Large

FUNCTION_PAYLOAD_TOO_LARGE

sfo1::5jmnt-1781246158332-7f21126d1f43
```

最开始直觉上容易以为是存储服务的问题，比如 Backblaze B2、R2 或 Vercel Blob 没配好。但最后复盘下来，根因并不在对象存储，而在上传链路。

只要文件先进入 Vercel Serverless Function 的请求体，就会受到 Vercel Function body limit 约束。后面无论再把文件转存到哪里，都已经晚了。

## 一、问题现象

Prompt Lens 的视频/图片分析流程大致是：

1. 用户在浏览器选择视频或图片。
2. 前端把文件上传到后端。
3. 后端把文件存到对象存储。
4. 后端再把媒体 URL 和抽帧结果交给分析接口。

之前的上传代码走的是典型的 `FormData` 方式：

```ts
const formData = new FormData();
formData.append("file", selectedFile);

const uploadRes = await fetch("/api/upload", {
  method: "POST",
  body: formData,
});
```

这个写法在本地开发和小文件上传时没有问题，但是到了 Vercel 线上，大文件会先打到 `/api/upload` 这个 Serverless Function。

文件体一旦超过 Vercel Function 能接收的请求体大小，就会直接在函数入口前后失败，报：

```text
413 Request Entity Too Large
FUNCTION_PAYLOAD_TOO_LARGE
```

这时后端代码里再判断 `file.size`、再生成预签名 URL、再调用 Blob/R2/B2 都没有意义，因为请求体已经被挡住了。

## 二、第一轮思路：用签名 URL 直传

第一轮尝试是给大文件生成签名 URL，让浏览器直接 PUT 到对象存储。

这个方向本身是对的，但当时还有一个关键错误：前端仍然先把文件放进 `FormData`，POST 到 `/api/upload`，然后后端在解析到 `file.size > 4.5MB` 后才返回签名 URL。

伪代码类似这样：

```ts
const formData = new FormData();
formData.append("file", selectedFile);

const uploadRes = await fetch("/api/upload", {
  method: "POST",
  body: formData,
});

const uploadData = await uploadRes.json();
if (uploadData.needDirectUpload) {
  await fetch(uploadData.uploadUrl, {
    method: "PUT",
    body: selectedFile,
  });
}
```

这个方案看起来像“直传”，但其实大文件已经先经过了 `/api/upload`。

真正的问题在第一步：

```text
浏览器 -> /api/upload
```

而不是：

```text
/api/upload -> 对象存储
```

所以这版仍然会被 Vercel Function body limit 拦住。

这次经验非常明确：判断文件大小和申请上传凭证的请求，不能携带文件本体。它只能携带元数据，比如文件名、大小、类型、目标路径。

## 三、第二轮思路：换成 Vercel Blob

后来把存储换成了 Vercel Blob。

但一开始仍然用了服务器代传方式：

```ts
import { put } from "@vercel/blob";

export async function POST(request: NextRequest) {
  const formData = await request.formData();
  const file = formData.get("file") as File;

  const blob = await put(key, file, {
    access: "public",
    token: process.env.BLOB_READ_WRITE_TOKEN,
  });

  return NextResponse.json({ url: blob.url });
}
```

这其实只是把“后端转存目标”从 B2/R2 换成了 Vercel Blob。

上传链路仍然是：

```text
浏览器 -> Vercel Function -> Vercel Blob
```

文件还是先进入 Function，所以 4.5MB 以上仍然会失败。

Vercel Blob 的 README 里其实也明确区分了两种方式：

1. Server upload：文件先发到服务器，再由服务器上传到 Blob。简单，但会受到 Function body limit 影响。
2. Client upload：浏览器直接上传到 Blob。复杂一点，但适合大文件。

这次要解决的就是第二种。

## 四、最终正确方案：Vercel Blob Client Upload

最终采用的是 Vercel Blob 的客户端直传。

正确链路变成：

```text
浏览器 -> /api/upload 申请上传 token
浏览器 -> Vercel Blob 直接上传文件
Vercel Blob -> /api/upload 回调上传完成
```

这里 `/api/upload` 不再接收文件本体，只负责：

1. 验证用户登录状态。
2. 做上传限流。
3. 校验文件类型。
4. 校验文件大小。
5. 生成 Vercel Blob client upload token。
6. 在上传完成回调里写操作日志。

文件内容完全不经过 Serverless Function。

### 1. 后端改成 `handleUpload`

上传 API 从原来的 `request.formData()` + `put(file)`，改为：

```ts
import { handleUpload, type HandleUploadBody } from "@vercel/blob/client";

export async function POST(request: NextRequest) {
  const body = (await request.json()) as HandleUploadBody;

  const jsonResponse = await handleUpload({
    request,
    body,
    token: process.env.BLOB_READ_WRITE_TOKEN,
    onBeforeGenerateToken: async (pathname, clientPayload) => {
      // 这里做登录校验、限流、文件类型和大小校验
      return {
        allowedContentTypes: [metadata.contentType],
        maximumSizeInBytes: maxSizeBytes(metadata.mediaType),
        tokenPayload: JSON.stringify({
          ...metadata,
          userId: session.user.id,
        }),
      };
    },
    onUploadCompleted: async ({ blob, tokenPayload }) => {
      // 这里记录 file.upload 操作日志
    },
  });

  return NextResponse.json(jsonResponse);
}
```

这一层的关键点是：`request.json()` 里只有 Blob SDK 的事件和客户端传来的元数据，没有文件二进制。

### 2. 前端改成 `@vercel/blob/client` 的 `upload`

新增了一个统一 helper：

```ts
import { upload } from "@vercel/blob/client";

export async function uploadMediaToBlob(file: File, onProgress?: (percentage: number) => void) {
  const mediaType = getMediaType(file);
  const pathname = `uploads/${mediaType}/${crypto.randomUUID()}-${safeFilename(file.name)}`;
  const contentType = file.type || (mediaType === "video" ? "video/mp4" : "image/jpeg");

  const blob = await upload(pathname, file, {
    access: "public",
    handleUploadUrl: "/api/upload",
    contentType,
    multipart: file.size > 5 * 1024 * 1024,
    clientPayload: JSON.stringify({
      filename: file.name,
      size: file.size,
      contentType,
      mediaType,
    }),
    onUploadProgress: ({ percentage }) => {
      onProgress?.(percentage);
    },
  });

  return {
    url: blob.url,
    filename: file.name,
    mediaType,
    size: file.size,
    key: blob.pathname,
  };
}
```

这里最重要的是：

```ts
upload(pathname, file, {
  handleUploadUrl: "/api/upload",
  multipart: file.size > 5 * 1024 * 1024,
});
```

SDK 会先请求 `/api/upload` 获取 token，然后直接把文件传到 Vercel Blob。

### 3. 页面里删除 `FormData(file)`

原来页面里的上传逻辑：

```ts
const formData = new FormData();
formData.append("file", selectedFile);
const uploadRes = await fetch("/api/upload", { method: "POST", body: formData });
const uploadData = await uploadRes.json();
```

改成：

```ts
const uploadData = await uploadMediaToBlob(selectedFile, (percentage) => {
  setProgress("Uploading file... " + Math.round(percentage) + "%");
});
```

这一步是整个修复里最关键的地方。

如果前端还保留 `fetch("/api/upload", { body: FormData(file) })`，后端怎么改都不算真正绕开 Function body limit。

## 七、踩坑总结

### 1. 换存储服务不等于解决上传限制

B2、R2、Vercel Blob 都可以存大文件。

但如果上传路径是：

```text
浏览器 -> Serverless Function -> 对象存储
```

那瓶颈就是 Serverless Function 的请求体限制，而不是对象存储能力。

### 2. 预签名 URL 必须在上传文件之前申请

错误模式：

```text
先 POST 文件到后端
后端发现文件太大
后端返回签名 URL
前端再直传
```

这个顺序是错的，因为第一步已经失败。

正确模式：

```text
前端只发文件元数据到后端
后端返回 token / 签名信息
前端直接上传文件到对象存储
```

### 3. `/api/upload` 不应该接收大文件本体

以后只要看到这种代码，就要警惕：

```ts
const formData = new FormData();
formData.append("file", file);
await fetch("/api/upload", { method: "POST", body: formData });
```

如果目标部署在 Vercel Function，并且文件可能超过几 MB，这个写法迟早会出问题。

### 4. 大文件入口要统一封装

这次新增 `uploadMediaToBlob` 的价值在于，后续所有视频、音频、图片上传都可以复用同一条链路。

不要每个页面自己写一套上传逻辑，否则很容易某个入口又退回 `FormData` POST。

目前已经修了：

- 视频/图片分析入口
- 音频分析入口

还需要后续检查：

```text
components/video-edit-tab.tsx
```

如果视频剪辑入口也允许上传大文件，也应该迁移到同一个 `uploadMediaToBlob`。

### 5. 环境变量也很关键

Vercel Blob client upload 仍然需要服务端生成 token，所以 Vercel 环境变量里必须有：

```text
BLOB_READ_WRITE_TOKEN
```

没有这个变量，前端不会再报 413，但会在申请上传 token 时失败。

## 八、以后处理同类问题的检查清单

以后遇到类似：

```text
413 Request Entity Too Large
FUNCTION_PAYLOAD_TOO_LARGE
```

可以按这个顺序查：

1. 前端是不是还在用 `FormData(file)` POST 到后端。
2. 后端是不是还在 `request.formData()` 或 `request.arrayBuffer()` 读取大文件。
3. 是否需要改成对象存储直传。
4. 申请上传凭证的请求是否只包含元数据。
5. 是否在服务端校验文件类型、大小和用户权限。
6. 是否有上传完成后的记录机制。
7. 是否配置了生产环境变量。
8. 是否还有其它页面绕过了统一上传 helper。

一句话总结：

> 大文件上传不要穿过 Serverless Function。Serverless 只发凭证、做校验、记日志；文件本体必须从浏览器直达对象存储。
