# 今日总结：修复《第139次崩塌》AI NPC 接口问题

今天主要处理了《第139次崩塌》项目里的 AI NPC 回复问题。

这个项目中，玩家可以在剧情节点里选择固定选项，也可以输入自己的自由回复。固定选项本来就是预设文案，但自由回复应该调用 DeepSeek API，让 NPC 根据玩家输入生成动态回应。实际测试时发现，NPC 回复表现得比较固定，因此开始排查是不是 API 又没有连上。

## 一、问题现象

在游戏里，NPC 回复主要有两类。

第一类是固定选项回复。玩家点击三个固定选项时，会显示预设文案，例如：

```js
reply: `${NPCS[speaker]?.name || 'NPC'}记住了你的选择。`
```

这部分固定是正常的，因为它本来就是剧情选项反馈。

第二类是自由输入回复。玩家在输入框中输入内容后，前端会请求：

```text
/api/npc-followup
```

这个接口应该由服务端调用 DeepSeek，生成动态 NPC 回复。

但线上测试时，接口返回了：

```text
POST https://let-him-survive.vercel.app/api/npc-followup
Status: 404
```

这说明线上环境并没有正确暴露 `/api/npc-followup` 接口。

## 二、原因分析

项目原本的后端接口写在：

```text
server/index.js
```

里面使用 Express 定义了：

```js
app.post('/api/npc-followup', async (req, res) => {
  // 调用 DeepSeek API
});
```

本地如果同时启动前端和后端，这种写法可以工作。

但线上部署到 Vercel 时，当前配置主要是构建前端：

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "framework": "vite"
}
```

也就是说，Vercel 会部署前端静态构建产物，但不会自动把 `server/index.js` 里的 Express 路由变成线上 API。

同时，`vite.config.js` 里的代理：

```js
server: {
  proxy: {
    '/api': 'http://localhost:3001',
  },
}
```

只在本地开发环境生效，线上 Vercel 不会使用这个代理。

所以最终结果就是：

```text
前端请求 /api/npc-followup
本地 Express 里有这个路由
但 Vercel 线上没有这个路由
线上请求直接返回 404
自由回复无法真正调用 DeepSeek
```

## 三、修复方案

修复方式是新增 Vercel Serverless Function：

```text
api/npc-followup.js
```

Vercel 会自动把 `api/` 目录下的文件部署成 API 路由。因此新增这个文件后，线上会有：

```text
/api/npc-followup
```

新的接口负责：

1. 接收前端传来的玩家输入。
2. 从服务端环境变量读取 `DEEPSEEK_API_KEY`。
3. 调用 DeepSeek Chat Completions API。
4. 根据当前场景和 NPC 人设生成回复。
5. 返回 `npcReply` 和 `nextQuestion`。

同时也顺手修了一个细节：前端传给后端的是中文 NPC 名字，比如“莉娅”“盖亚”，所以新的 API 同时兼容中文名和英文 key，避免人设映射失效。

## 四、环境变量与部署问题

修复接口之后，还需要在 Vercel 项目里配置环境变量：

```text
DEEPSEEK_API_KEY
```

这个 key 必须放在 Vercel 服务端环境变量里，不能放进前端的 Vite 环境变量中，否则会有泄露风险。

配置完成后，尝试重新部署时遇到了 Vercel 的提示：

```text
Prebuilt deployments cannot be redeployed because they will not use the latest environment variables and project settings.
Please create a new deployment instead.
```

这是因为当前项目使用的是 GitHub Actions + Vercel prebuilt deployment。旧的 prebuilt 部署不能直接 redeploy，否则不会使用最新的环境变量和项目设置。

正确做法是：提交新的代码并 push 到 `main`，让 GitHub Actions 创建一个新的 Vercel deployment。

## 五、提交与验证

本次新增了：

```text
api/npc-followup.js
```

然后进行了本地验证：

```bash
node --check api/npc-followup.js
npm run build
```

语法检查和前端构建都通过。

之后提交并推送到 GitHub，触发新的 Vercel 部署。部署成功后，再次测试线上接口：

```text
POST https://let-him-survive.vercel.app/api/npc-followup
Status: 200
```

返回结果示例：

```json
{
  "npcReply": "你终于来了。这片废墟里，你看到了什么？",
  "nextQuestion": "如果必须放弃一样东西才能离开，你会选择什么？"
}
```

这说明线上 `/api/npc-followup` 已经不再是 404，并且可以正常调用 DeepSeek 生成 NPC 动态回复。

## 六、今日结论

今天的问题本质不是 DeepSeek API 本身坏了，而是线上部署时没有正确暴露后端接口。

这次修复后，项目的 AI NPC 自由回复链路变成了：

```text
前端自由输入
  -> /api/npc-followup
  -> Vercel Serverless Function
  -> DeepSeek API
  -> 返回 npcReply / nextQuestion
  -> 前端展示 NPC 回复
```

今天的主要收获是：

1. Vercel 部署 Vite 前端时，不会自动部署 Express server。
2. 线上 API 应该放到 `api/` 目录，使用 Vercel Serverless Function。
3. 本地 Vite proxy 只对本地开发有效，不能代表线上 API 可用。
4. 环境变量填完后，需要创建新的部署，不能复用旧的 prebuilt deployment。
5. 判断 AI 接口是否连通，最直接的方法是测试真实线上接口状态码和返回内容。

这次修复后，《第139次崩塌》的自由输入 NPC 回复已经可以正常走 AI 生成，不再只是固定文案或失败兜底。
