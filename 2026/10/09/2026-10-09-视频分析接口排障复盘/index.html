一次视频分析接口排障：为什么页面总是返回空结果并且显示错误

这次测试视频分析功能，这个AI就会甩锅，自己接口用了兼容接口没用原生接口导致一直500错误，没有加以测试就甩锅服务商模型错误。

用户看到的现象很直接：视频上传了，镜头能播放，但分析等待很久，最后提示词仍是空的。有时出现 Unexpected end of JSON input，有时显示 Analysis interrupted。后来排查到部分模型请求返回了 {"code":500,"msg":"Network error, please try again later."}。

第一次 Debug：模型有返回，页面却保存了空结果

1. 遇到了什么报错

视频分析完成后，提示词区域没有内容，镜头显示待复核，页面出现 Analysis interrupted。测试过程中还出现过 Unexpected end of JSON input。

这几个现象涉及不同的处理环节，需要分别排查。

2. 是什么原因导致的

是因为写的结果校验把有效分析丢掉了。

同一素材复现时，模型确实返回了画面描述和提示词，但 story 是一段文字；代码要求它必须是对象，因此判整份结果失败，最后保存成空提示词。

问题在主应用的分析结果处理代码。

另外，Unexpected end of JSON input 表示读取响应时，没有拿到完整、有效的 JSON。它与 story 字段校验失败属于两个问题：前者发生在响应解析阶段，后者发生在分析内容校验阶段。仅凭这条报错，无法确定当时响应为空或不完整的具体原因。

3. 最后怎么解决的

已经修正：

  • 文字形式的 story 转成摘要，保留有效分析。
  • 真正缺字段时，记录具体缺哪项。
  • 明确告诉模型每个字段应是什么格式。

响应读取也进行了调整：检查响应类型和业务错误；原生接口的流式响应按事件逐段解析；响应没有完整结束时明确报错，避免保存不完整结果。

此前确认分析按钮无法继续的问题，则单独修复了报价恢复逻辑，避免异常恢复后按钮仍被锁住。

第二次 Debug：兼容接口持续报错，误判成服务商故障

1. 遇到了什么报错

继续测试时，分析等待很久，最终仍然失败。排查发现，接口虽然返回 HTTP 200，正文却包含业务错误：

Gemini 2.5 Flash 则返回：

看到 Network error 后，AI过早把原因归到网络或服务商模型故障，用户要求再次排查。

2. 是什么原因导致的

当时使用了 OpenAI 兼容接口。对照测试中，使用同一份 Key、同一个模型，兼容路径返回业务错误，原生 Gemini 路径能够成功回复 OK。

这个结果把问题定位到了接口路径：当前测试环境下，四个模型的兼容路径调用失败，原生路径调用成功。至于兼容路径内部为什么报错，目前没有足够证据继续下结论。

接入过程还有两个疏漏：没有充分实测就认为模型已经接通，以及把服务端返回的 Network error 直接当成根因。

3. 最后怎么解决的

Gemini 3.5、3.6、3.7、3.8 Flash 全部切换到原生接口，并同步调整请求格式与流式响应解析。

四个模型逐个发送最小的 OK 请求，全部成功。每个消耗 0.01 个 KIE 积分，本轮合计 0.04 个。

Gemini 2.5 Flash 的兼容和原生路径均返回“通道不支持”，因此删除了模型选项及对应配置

总结一下AI使用的几个麻烦的地方：

1.旧代码老留着不删，我亲自看文件时才发现

2.不会推测真实用户的操作导致在写代码上闹一些笑话，比如不知道人类会上下滚动页面，导致翻过去的存储资源直接删除后面翻回来时重复加载

3.流程繁琐不精简，总喜欢在页面上写好多重复入口

4.喜欢甩锅，不深度验证就赖是外部服务错误不是他自己的问题
