今日总结-2026-07-06-无限画布 AI 视频模板功能上线复盘

从“能跑”到“能上线”：一次无限画布 AI 视频功能开发复盘

今天主要做的是一个具体功能的完整开发：让无限画布支持 AI 生成 1 分钟左右的视频模板。这个功能看起来像是“点一下生成视频”，但真正做下来才发现，它其实不是一个简单按钮，而是一整条工作流。

一、今天做了什么

今天实现的是“多幕合一视频”的基础能力。整体流程是：

也就是说，它不是让 AI 一次性生成一个 60 秒视频，而是先生成多个短片段，再把这些片段拼接起来。默认方案改成了使用 Veo 3.1 Lite 测试：8 幕，每幕约 8 秒，合计约 64 秒，更适合本地测试和成本控制。

二、今天接触到的核心模块

这次工作是偏全栈的，但重心更偏后端、AI 集成和工程化。前端部分主要是无限画布编辑器，包括 Scene 节点、Composition 合成节点、AI 模板弹窗、生成所有片段按钮和合成最终视频按钮。

后端部分包括生成 AI 模板的 server action、保存节点和连线数据、提交视频任务、轮询任务状态、webhook 接收生成结果，以及把合成结果写回数据库。

AI 集成部分包括用聊天模型生成分镜 prompt、用 KIE 的 Veo 3.1 Lite 生成视频、适配 Veo 专用接口、处理不同模型的 payload 和状态返回。数据库部分则涉及 Canvas 项目表、视频任务表、D1 migration 和本地 D1 测试。

三、最大的问题：浏览器渲染错误

今天最折磨人的问题是浏览器不断报这个错：

一开始以为是弹窗组件写法有问题，于是先排查 Dialog。后来发现即使不用 Dialog，还是可能报错。继续排查后发现，Radix 的 Select 也会用 Portal 插入 DOM。为了降低风险，把 AI 模板弹窗里的 Radix Dialog 和 Select 都移除了，改成普通 fixed 弹窗和原生 select。

但最后错误仍然可能出现在页面挂载点，这说明问题不一定是业务代码本身，而可能是浏览器插件在修改 DOM。这个错误非常像浏览器翻译插件导致的 React DOM 不一致，比如 Chrome 自动翻译、沉浸式翻译、划词翻译、双语网页翻译插件。

这些插件可能会把 React 管理的文本节点拆开、替换、包一层 span。React 下一次更新时，以为某个节点还在原来的父节点下面，结果已经被插件改了，于是 insertBefore 就崩了。最后给 Canvas 页面和编辑器根节点都加了 notranslate 和 translate=”no”。

这件事给我的教训是：高动态 React 页面，尤其是 ReactFlow、Portal、拖拽、弹窗这些场景，开发时一定要关掉网页翻译插件。不然很容易把浏览器插件的问题误判成业务代码问题。

四、测试不能只跑类型检查

今天一开始只跑了类型检查。类型检查通过了，但这不代表功能完整可靠。后来补了测试，才发现测试链路本身也有问题。

新增了 Canvas 场景排序测试，以及 KIE Veo Lite payload 和状态映射测试，覆盖 Scene 节点拓扑排序、Composition 节点查找、Veo Lite payload、参考图转视频 payload、Veo 状态码映射，以及 Veo 模型是否走专用 record-info 查询接口。

后来完整跑测试时，D1 测试失败，错误是 Wrangler returned no JSON output。排查后发现不是数据库本身的问题，而是测试 helper 在 Windows 下直接执行 wrangler.cmd 会失败，导致没有 stdout，所以自然解析不到 JSON。最终修复方式是不用 .cmd，改成直接用 Node 执行 Wrangler 的 JS 入口。

修完后，完整测试和类型检查都通过了。这件事的教训很直接：以后推送前不能只跑类型检查，必须跑完整测试。测试没过就不能说完成，更不能推。

五、今天真正学到的东西

今天最大的收获不是写了多少代码，而是理解了一个完整功能上线背后的链路。一个 AI 视频功能不是只有“调用模型”这么简单，它至少包括用户输入、prompt 规划、节点数据结构、任务提交、异步生成、webhook 回调、数据库存储、文件转存、最终合成、错误恢复、测试验证。

以前我可能会觉得“AI 生成视频”就是调一个 API。但今天做完之后会发现，真正难的是把它稳定地接进产品工作流里。

六、我需要补的知识点

  1. React DOM 和浏览器插件冲突：理解为什么翻译插件会导致 React 的 insertBefore 报错。
  2. ReactFlow 的 nodes / edges：画布不是普通列表，而是图结构，播放顺序应该由 edges 决定。
  3. 拓扑排序：多幕视频合成前，必须从连接关系里推导出正确顺序。
  4. Webhook 异步任务：视频生成不是同步返回结果，而是先提交任务，完成后由平台回调。
  5. Cloudflare D1：D1 是 Cloudflare 的 SQLite 数据库服务，本地测试依赖 Wrangler。
  6. 测试意识：tsc 只能证明类型没错，不能证明功能没错。以后必须完整跑测试。

七、今天最值得手写的函数

今天最适合自己手写一遍的是场景排序函数。需求是：输入 nodes 和 edges，输出按播放顺序排列的 Scene 节点。

这个函数能帮助我真正理解为什么 Canvas 是图、为什么连线决定播放顺序、为什么 Composition 是出口、为什么多幕视频可以合成为一个完整视频。如果我能自己写出这个函数，就说明我不是只知道“点按钮生成”，而是真的理解了这个功能的数据结构。

八、今天的经验教训

  1. 开发时不要被“页面能打开”骗了。能打开不代表功能完整，必须跑测试。
  2. 浏览器环境也会制造 bug。以后遇到奇怪的 React DOM 错误，要第一时间用无痕窗口、关闭插件验证。
  3. AI 功能不是只调模型。真正上线时，模型只是其中一环，后面还有任务管理、回调、存储、合成、测试和错误处理。

九、总结

今天做的事情让我意识到，一个看似简单的 AI 视频模板功能，背后其实是完整的工程系统。它包含前端画布、后端 action、数据库、AI 模型、第三方 API、webhook、R2 存储、测试和浏览器兼容问题。

今天最大的进步不是“功能写完了”，而是开始意识到：功能上线不是写完代码，而是能解释清楚它怎么工作、能测、能排错、能复盘。
