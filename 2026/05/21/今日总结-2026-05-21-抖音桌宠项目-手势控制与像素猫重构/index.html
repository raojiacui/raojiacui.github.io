今日总结-2026-05-21-抖音桌宠项目-手势控制与像素猫重构

今日总结 2026-05-21

项目：抖音陪伴桌宠 - 参赛项目”抖音AI创变者大赛”

一、遇到的主要困难

1. 像素猫 CSS 渲染问题

问题描述：CSS 编写时出现孤立代码块，.pixel-cat-torso 块里残留了 top、width 等属性导致 LightningCSS 报错。

解决办法：删除孤立的 CSS 声明块，只保留 { display: none; }。

2. useDrag 的 setPosition 命名冲突

问题描述：原 useState 返回的 setPosition 和自定义的 setPosition 函数重名，导致递归调用。

解决办法：将 state 的 setter 重命名为 setPositionState，自定义函数保留 setPosition。

3. 摄像头权限被拒绝（已允许仍报权限错误）

问题描述：摄像头权限已授予，但一直报”摄像头权限被拒绝”。

原因：错误信息覆盖问题，error state 没有在关闭手势时清空。

解决办法：在 toggleEnabled 关闭时添加 setError(null)。

4. MediaPipe Hands “Hands不是构造函数”

问题描述：动态导入 @mediapipe/hands npm 包后，new Hands() 报错。

原因：ES Module 打包后导出方式不同，直接 import 拿不到正确的类。

解决办法：改用 CDN 加载脚本方式，通过 document.createElement('script') 加载 hands.js，挂载到 window.Hands。

5. 手势控制和鼠标拖拽冲突

问题描述：开启手势后，手掌位置的 setPosition 持续更新，导致 React re-render，isDragging 状态丢失，鼠标拖拽失效。

原因：Gesture → setPosition → re-render → useDrag 状态重置。

解决办法：

  1. 在 useEffect 中判断 !isDragging 才更新位置
  2. 手势控制期间不触发 re-render 问题，通过 LERP 插值在 hook 内部平滑处理

6. 手势控制启用后鼠标拖不动

问题描述：开启手势后，即使关闭手势，鼠标也拖不动小猫。

原因：

  1. 视频元素虽然 display: none，但仍捕获 Pointer Events
  2. pointer-events: all 影响布局容器

解决办法：

  1. 视频元素添加 pointerEvents: 'none'
  2. 手势控制的状态通过 gestureEnabled prop 控制是否生效
  3. 确保 gesturePosition 变化时只在 gestureEnabled && !isDragging 时更新

二、核心实现方案

1. 像素猫渲染（纯CSS）

2. 手势控制架构

3. 状态管理
