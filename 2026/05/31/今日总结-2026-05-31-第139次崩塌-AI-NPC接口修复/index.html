六、今日结论

今天的问题本质不是 DeepSeek API 本身坏了，而是线上部署时没有正确暴露后端接口。

这次修复后，项目的 AI NPC 自由回复链路变成了：

今天的主要收获是：

  1. Vercel 部署 Vite 前端时，不会自动部署 Express server。
  2. 线上 API 应该放到 api/ 目录，使用 Vercel Serverless Function。
  3. 本地 Vite proxy 只对本地开发有效，不能代表线上 API 可用。
  4. 环境变量填完后，需要创建新的部署，不能复用旧的 prebuilt deployment。
  5. 判断 AI 接口是否连通，最直接的方法是测试真实线上接口状态码和返回内容。

这次修复后，《第139次崩塌》的自由输入 NPC 回复已经可以正常走 AI 生成，不再只是固定文案或失败兜底。
